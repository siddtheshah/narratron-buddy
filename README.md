This project uses the Google Agent Development Kit (ADK) and Gemini Live API to create an interactive agent. It features a FastAPI web interface to provide a collaborative doodle canvas and display images generated by the agent.

## Prerequisites

- Python 3.13+
- Node.js 22 and npm (for the canvas TypeScript build)
- [`uv`](https://github.com/astral-sh/uv) (fast Python package and project manager)
- Windows (PowerShell examples below)

## Installing `uv`

If you do not have `uv` installed, follow the official installation guide from Astral:
- [Astral `uv` Installation Documentation](https://docs.astral.sh/uv/getting-started/installation/)

## Install

Install Python dependencies (including development and test tools) using `uv`:

```powershell
uv sync --locked
```

Install and build the frontend dependencies from the repository root:

```powershell
npm ci
npm run build
```

Server startup rebuilds missing or stale canvas assets automatically. Use
`npm run watch` to rebuild TypeScript changes while the server is running.

See [Testing in AGENTS.md](AGENTS.md#testing) for development checks, local
testing, and load tests.

### Gcloud Setup

You will need a GCloud project to use the Gemini Live API.

To get started with GCloud, complete the following steps:
1. Install GCloud CLI: https://cloud.google.com/sdk/docs/install
2. Run `gcloud init` to login and set your default project
3. Run `gcloud auth application-default login` to grant Python local access to your credentials

## Running the App

Games use the CEL-Go worker by default. Build the local binary before starting:

```powershell
go -C game_engine/cel_go_worker build -trimpath -o ../../scratch/cel-go-worker.exe .
```

On Linux/macOS, omit `.exe`. Go 1.23 or newer is required to build the worker.
`NARRATRON_CEL_GO_WORKER` can point to another binary. The app uses a lazy pool
of two workers per Python process; set `NARRATRON_CEL_GO_POOL_SIZE` (1–32) to
change its size. Operations borrow an idle worker with a bounded wait, and
packages are cached independently on each worker. Dead workers restart on reuse.
Set `NARRATRON_CEL_BACKEND=python` to explicitly select the legacy backend, or
`auto` to allow fallback when the binary is absent. The default `go` setting
requires the binary. The Dockerfile builds and installs the Linux worker and
selects the same Go backend and pool size for Cloud Run.

SVG packages are limited to 64 assets and 1 MiB of source data before parsing,
with the existing 128 KiB per-file limit. Go operations share a 4 MiB aggregate
conversion and SVG expansion budget across rendering, model state and draft
candidates, in addition to the wire-frame and individual-value limits.

### Start the Combined Web Canvas
This runs both the web viewer and the bidi agent WebSocket server on port 8000:
```powershell
uv run main.py
```
- Open http://localhost:8000 to open the app.

## Phone Remote

Open the deploy page on your phone and tap a theater's phone button to open
its remote, or visit `/remote?theater_id=YOUR_THEATER_ID`. You can also open `/remote`
and paste a canvas link or theater ID. Sign in on the phone using the account
that currently holds the orator baton. Both devices must reach the same Narratron
server; a phone cannot reach your computer through a `localhost` URL.

The remote supports scene history, new images and music, scene and music pins,
story and interactable updates, audience collaboration, and typed instructions.
Keep the main canvas open for audio playback and microphone input. Start
Narratron there to enable generation and instructions. The remote checks access
and state every three seconds while visible; commands use the existing protected
orator APIs. A join link alone does not grant control.
The full canvas is available on desktop. Mobile canvas visits redirect to the
remote, and mobile deploy actions open the remote instead of the canvas.

## Exporting the Frontend

You need to set up ngrok to expose the frontend. https://dashboard.ngrok.com/get-started/setup
Create a username and password in your `ngrok_policy.yaml`. This will prevent you getting DDOS'd by random people.

```powershell
ngrok http 8000 --traffic-policy-file ngrok_policy.yaml
```

## Content Management

In cloud mode, deploying a preset adventure downloads its folder directly
through the GCS Python transfer manager with up to eight concurrent transfers.
The mounted `/mnt/storage/adventures` directory still supplies package listings
and resolves adventure IDs to folder names. `GCS_BUCKET` defaults to
`narratron-buddy-app-storage` and `GCS_ADVENTURES_PREFIX` to `adventures`; set them
to match the mounted source. Downloads use Application Default Credentials with
permission to list and read those objects. Temporary downloads are removed after
the existing package parser reads them, including on failure. Local mode and
explicit local adventure directories continue to read from disk. Repository
persistence remains in the background after deployment.

Game and adventure content can be backed up to separate Git repositories under
`gs://narratron-buddy-app-storage/git/` without adding packages to this source
repository. Use `uv run python scripts/content.py upload` to snapshot, commit,
and push local content, `download` to restore versioned content, and `publish`
to deploy an uploaded commit to the app-served GCS folders. Add `--content games`
or `--content adventures` to select a collection. Run
`uv run python scripts/content.py --help` for setup and recovery instructions.
